Approach

1. One fixed macro

Pick up → swirl → place → back-off. A single smooth horizontal orbit at travel height — no fragile multi-part choreography, no vision, no per-item tuning. The macro is deterministic, so every recording is comparable. (It's locked in for the hackathon: repeatable_grasp.py --swirl-smooth.)

2. Ten explicit physical features

The torque time series becomes a 10-D vector z. No learned encoder — each feature has a physical meaning, shown with plain-language explanations in the dashboard:

GroupFeaturesWhat they capture
Static liftmass_j2, mass_j3*, lift_dyn_j3Gravity torque offsets = mass estimate; inertial cue from the lift
Swirl dynamicsswirl_var_j2, swirl_var_j3, swirl_ptp_j3, phase_lag_s, rattle_eSlosh energy; shifting-mass swing; TCP–torque phase lag = viscous damping; rattle energy (observable band only — the 5–25 Hz band needs 100 Hz on-robot sampling)
Grip & excitationgrip_comp, swirl_speed*Gripper compliance under load, squishy vs rigid; TCP swirl speed for excitation normalization

* Kept in the 10-D vector for display; zero-weighted in the embedding — the static offsets sit below tare noise, and swirl speed measures the fixed macro's drive rather than the contents. The matcher effectively works in 7-D.

3. Scale, normalize, retrieve

e = Wz / ‖Wz‖₂          # per-feature scales W, then L2 normalization
ĉ = vector search        # MongoDB Atlas $vectorSearch, cosine, top-k

W is a diagonal matrix: per-feature scales stop the largest-magnitude raw feature (swirl speed, ~160 mm/s) from drowning the small ones (variances ~1–5), and three entries are zero — the static mass offsets and swirl speed are excluded from matching (see above), so the unit embedding lives in the 7 informative dimensions.

Retrieval proposes, a supervised head disposes. Atlas $vectorSearch finds the neighborhood (and powers the vector-space plot), but the actual call is made by a shrinkage-LDA classifier fit in milliseconds on the whole labeled library — every prediction refits, so teaching a new item takes effect immediately with no training step and no deployment. On 21 held-out cups the LDA head gets the category right 52% of the time, vs 24% for pure nearest-neighbor retrieval on the same features. Its per-prediction probabilities are uncalibrated, so the dashboard shows the measured accuracy instead of a made-up confidence score. Predictions are reported at three levels — category (liquid / solid / empty), material (water, screws, …), and the closest taught item — so the headline claim stays within what the signal can actually support.

4. Teach without training

A new item is learned by storing one embedding — atlas.teach(label, e). The next query searches it immediately. There is no model to retrain and no deployment step, which is the whole point of the non-parametric design.

5. Keep the protocol fixed

We measured this: the same cup scores ~0.4 cosine similarity across swirl/non-swirl protocols, while different items within one protocol reach ~0.9. The embedding encodes the motion as much as the contents — so the library admits swirl-protocol recordings only, and the dashboard always records with the swirl macro.

What we don't do. No deep learning, no learned encoder, no FFT peak-picking (there isn't enough bandwidth for it at 4–5 Hz). The dashboard labels the rattle band honestly: observable-band energy only, with the 5–25 Hz band marked as requiring 100 Hz on-robot sampling.
