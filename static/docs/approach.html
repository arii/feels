Approach

1. One fixed macro

Pick up → swirl → place → back-off. A single smooth horizontal orbit at travel height — one deterministic motion, so every recording is comparable. (It's locked in for the hackathon: repeatable_grasp.py --swirl-smooth.)

2. Ten explicit physical features

The torque time series becomes a 10-D vector z whose features each have a physical meaning, shown with plain-language explanations in the dashboard:

GroupFeaturesWhat they capture
Static liftmass_j2, mass_j3*, lift_dyn_j3Gravity torque offsets = mass estimate; inertial cue from the lift
Swirl dynamicsswirl_var_j2, swirl_var_j3, swirl_ptp_j3, phase_lag_s, rattle_eSlosh energy; shifting-mass swing; TCP–torque phase lag = viscous damping; rattle energy (observable band only — the 5–25 Hz band needs 100 Hz on-robot sampling)
Grip & excitationgrip_comp, swirl_speed*Gripper compliance under load, squishy vs rigid; TCP swirl speed for excitation normalization

* Kept in the 10-D vector for display; zero-weighted in the embedding — the static offsets sit below baseline noise, and swirl speed measures the fixed macro's drive rather than the contents. The matcher effectively works in 7-D.

3. Scale, normalize, retrieve

e = Wz / ‖Wz‖₂          # per-feature scales W, then L2 normalization
ĉ = vector search        # MongoDB Atlas $vectorSearch, cosine, top-k

W is a diagonal matrix: per-feature scales stop the largest-magnitude raw feature (swirl speed, ~160 mm/s) from drowning the small ones (variances ~1–5), and three entries are zero — the static mass offsets and swirl speed are excluded from matching (see above), so the unit embedding lives in the 7 informative dimensions.

Atlas $vectorSearch finds the neighborhood (and powers the vector-space plot), but the call is made by a shrinkage-LDA classifier refit on the whole library at every prediction — teaching a new item takes effect immediately. On 21 held-out cups: category right 52% of the time, vs 24% for pure nearest-neighbor on the same features. LDA probabilities are uncalibrated, so the dashboard shows the measured accuracy, not a per-prediction score. Predictions come at three levels — category (liquid / solid / empty), material (water, screws, …), closest taught item — so the headline stays inside what the signal supports.

4. Teach by example

A new item is one stored embedding — atlas.teach(label, e). The next query searches it.

5. Keep the protocol fixed

Same cup, ~0.4 cosine across swirl/non-swirl protocols; different items within one protocol reach ~0.9. The embedding encodes the motion as much as the contents — the library admits swirl-protocol recordings only.

The system is a 10-D hand-built feature extractor plus vector search over taught examples. Rattle energy is reported for the observable band only; the 5–25 Hz band requires 100 Hz on-robot sampling.
