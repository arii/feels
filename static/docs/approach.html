Approach

1. One fixed macro

Pick up → swirl → place. A single smooth horizontal orbit at travel height — no fragile multi-part choreography, no vision, no per-item tuning. The macro is deterministic, so every recording is comparable. (It's locked in for the hackathon: repeatable_grasp.py --swirl-smooth.)

2. Ten explicit physical features

The torque time series becomes a 10-D vector z. No learned encoder — each feature has a physical meaning, shown with plain-language explanations in the dashboard:

GroupFeaturesWhat they capture
Static liftmass_j2, mass_j3, lift_dyn_j3Gravity torque offsets (mass estimate) + inertial cue during lift
Swirl dynamicsswirl_var_j2/j3, swirl_ptp_j3, phase_lag_s, rattle_eSlosh energy, shifting-mass swing, viscous lag of torque behind motion, high-frequency energy
Grip & excitationgrip_comp, swirl_speedCompliance under load; normalization for how hard the swirl was driven

3. Scale, normalize, retrieve

e = Wz / ‖Wz‖₂          # per-feature scales W, then L2 normalization
ĉ = vector search        # MongoDB Atlas $vectorSearch, cosine, top-k

Per-feature scaling stops the largest-magnitude raw feature (swirl speed, ~160 mm/s) from drowning the small ones (variances ~1–5). Retrieval averages similarity per label over the top-k hits; below 0.82 the UI flags low confidence instead of guessing.

4. Teach without training

A new item is learned by storing one embedding — atlas.teach(label, e). The next query searches it immediately. There is no model to retrain and no deployment step, which is the whole point of the non-parametric design.

5. Keep the protocol fixed

We measured this: the same cup scores ~0.4 cosine similarity across swirl/non-swirl protocols, while different items within one protocol reach ~0.9. The embedding encodes the motion as much as the contents — so the library admits swirl-protocol recordings only, and the dashboard always records with the swirl macro.

What we don't do. No deep learning, no learned encoder, no FFT peak-picking (there isn't enough bandwidth for it at 4–5 Hz). The dashboard labels the rattle band honestly: observable-band energy only, with the 5–25 Hz band marked as requiring 100 Hz on-robot sampling.
