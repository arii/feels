How to record

The classifier only knows what it has felt. This page is the data-collection protocol: what to record, what good data looks like, and the pipeline's acceptance criteria. Follow it and the signatures stay comparable across runs.

What to record

First, the confound set — the core of the experiment. Four items at the same mass, different contents:

  • solid_150g — a rigid 150 g weight
  • water_150g — 150 g of water
  • candy_150g — 150 g of loose candy
  • soap_150g — 150 g of dish soap

These four weigh the same — the baseline reads identical. Separation comes from dynamics alone; that is the claim being tested.

Then the basics: empty_cup, water_075pct, solid_020g, screws_100g. Record 2–3 repetitions per item; repeats are what let the matcher average out run-to-run noise.

The venue currently has water, solid weights, screws, and empty cups — record the confound set as props allow. The same-mass contrast is the point; partial coverage still teaches the system something.

How to record

  1. Swirl protocol only. One continuous pick → swirl → place → back-off, run with python repeatable_grasp.py --object <label> --record --swirl-smooth (or the dashboard's Mode 1 / Mode 2 buttons, which run exactly this).
  2. Same cup, same placement every run. The gripper reports one number; a different cup changes it and pollutes the grip feature.
  3. Baseline before each session. The extractor QCs the INIT baseline of every recording — preview any batch with teach_csv.py --dry-run recordings/ and read the baseline= flags before teaching.

Good = the SWIRL phase is present in the phase column and the baseline flags are clean. Skipped = anything teach_csv.py --require-swirl refuses: recordings with no SWIRL samples, or a baseline sampled mid-motion.

Recording requirements

  • Non-swirl motions. The embedding encodes motion as much as contents — measured: the same item recorded under two protocols scores 0.41–0.45 cosine, while different items under one protocol reach 0.92. Keep one protocol per library so the embedding encodes the cup.
  • Partial or interrupted runs. An aborted macro leaves a truncated phase sequence; the extractor's windows assume the full pick → swirl → place → back-off.
  • Teach labeled files. Files labeled mystery are held out for testing (--include-mystery overrides).

Teaching what you recorded

  • Live, one item at a time: Mode 2 on the dashboard. The preset chips fill in confound-set and basics labels; the run teaches straight into Atlas.
  • Batch: python teach_csv.py --require-swirl recordings/ teaches every labeled CSV with a true SWIRL phase and skips the rest.
  • Re-teach: --force replaces existing signatures for the same CSVs (dedup is on properties.csv).
  • Preview: --dry-run lists what would be taught, with phase source and baseline flags per file. Run it before every batch.

New signatures take effect on the next prediction — teaching is the training step.
